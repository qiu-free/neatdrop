七组各有 24 个相关变体：正向 9、稀疏反例 11、示例上下文 3、混合冲突 1。每组正向首选子类 `0/9 → 9/9`，每组 11 个稀疏反例均拒判，每组 3 个示例披露 `example_context`，每组冲突披露 `competing_categories`。所有新用途均待复核，没有普通建议。JSON 的 `by_group`、`by_family` 和逐条预测提供完整对照。

旧40场景的主类、子类、决策等级、复核原因、保留原名行为及质量状态均零变化。未解决的旧回归边界仍保留：非标题学习描述、研究叙述、口语会议等场景仍可能拒判；这次没有把旧40的31/35提高。此前八用途88个变体和质量9例行为也零变化。

收益证据限于已声明的内容模式：新用途需要明确正文锚点及至少两组非空字段；公共服务缴费还要求费用项目和成功状态，研究数据还要求研究背景与观测/变量证据。OCR 模拟载荷在基线会被普通物品视觉覆盖的7例现在保留用途候选。混合合同7例从普通建议转为披露冲突的候选。缺少锚点、文件名或扩展名单独命中、重复同组、空标签、占位和否定仍不赋予新用途。

`parsed_content` 变体只检查已提取文本在 DOCX/PPTX/XLSX/CSV 记录扩展名下不改变用途；TAB 变体检查真实表格分隔字段及空值。不执行格式解码，不能将其计为解析器准确率收益。真正字节容器、安全解析、API复制及资料库流程由格式集成测试单独验证。新增单元回归另含实际 CSV 字节经 `extract_document` 后进入 `analyze_local` 的缴费例子。

限制：规则使用中文显式锚点与字段，未覆盖所有自然语言、英语、机构格式、布局或未知否定语法。TAB 只在已知字段名之后作为分隔符，普通空格不能创造字段；没有推断任意表格列语义。用途规则用 NFKC/casefold 匹配，并将命中区间映射回有界原文，保留字段空格、大小写、冒号与 TAB 的连续片段；此前旧普通规则证据仍沿用规范化文本。没有真实用户代表性冻结集、校准或独立发布测试；这些类别继续 `candidate_only`，也未验证真人新手体验。

可复现输入和输出分别为 `v7-development.json`、`v7-development-results.json`。输出含源码指纹及运行时 Git HEAD，后续集成修改 `analysis.py` 时应重新运行并保留新指纹，不把不同引擎结果混为同一版本。

独立审查增补：初版虽然旧40零变化，但 `无。`、`尚未采集/填写` 及 TAB 空单元格后备注列不在该40场景中，曾造成错误用途候选。修复将句末标点只用于缺失标记判断，保留“无锡银行”“无刷电机”等实值；TAB只读取紧邻单元格。增补13例作为独立 `review13` 组报告，不改旧40或旧八用途分母。7例无标签全部拒判；6例真实名称、有效状态及连续原文依据全部得到候选。全对照共338个相关开发场景行为检查通过；这不改变合成集的局限。
