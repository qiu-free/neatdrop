# v7 document format extraction report

Task 1 implements real DOCX/PPTX/XLSX/CSV extraction through `prepare_input`, workspace previews, analysis jobs and trusted library previews. No dependencies were added. Existing byte reads, same-handle archive identity/size/mtime/hash verification, copy, receipts and undo remain the shared path. `GET /api/v1/config` adds `supported_extensions` (sorted extension strings); existing supported/reason scan fields remain compatible. Scan support means an eligible format; damaged files receive a per-file parser error when opened or analyzed.

## Read policy and API

- DOCX: main document paragraphs and table text in document order. Adjacent cells of the same table row are separated by TAB; distinct paragraphs and rows use newline. Direct vanish/webHidden runs and deleted/moved-from content are omitted. Headers, footers, footnotes, endnotes and comments are not read and their presence is disclosed. This does not render Word layout or resolve style-inherited visibility.
- PPTX: slide IDs and relationships determine real slide order; DrawingML text includes text shapes and table paragraphs. Hidden slides and directly hidden shapes are omitted. Notes/comments are omitted and disclosed. Masters, layouts, charts, images, SmartArt and embedded objects are not rendered or OCRed.
- XLSX: real workbook/worksheet/shared-string relationships; visible sheet names, visible rows/cells; shared strings, inline strings and raw stored values. Same-row cells use TAB. Hidden sheets/rows/columns are omitted and disclosed. Formula expressions are never exposed as extracted text or evaluated; only an existing `<v>` cache is read. Formula caches may be stale; formulas without caches and error cells are omitted with partial-read flags. No style/number/date formatting is applied, and the summary states this. No Office process is launched.
- CSV: strict UTF-8 (optional BOM), RFC-style quoted fields, escaped quotes and multiline fields. Delimiter detection is bounded to 8192 characters and comma/semicolon/TAB; fallback is comma. Logical records have 1-based row locations. CSV values are plain extracted text: a leading `=` is never executed or sent to a spreadsheet evaluator.

New payloads preserve `{text, sample, truncated, sampling}`. `sampling.kind` is `docx`, `pptx`, `xlsx` or `csv`; `separator` is newline between independent units (same-row cells can use TAB). Each segment has original unit-relative `start/end`, explicit sampled-text `sample_start/sample_end`, plus paragraph/table/row, slide, or sheet/cell/row locations. Exact sampled offsets avoid assuming that every boundary is newline. `analyze_local` maps these locations into evidence items. An omitted part of content sets `truncated`; collection/character caps set `budget_exhausted`. Existing quality/decision gates then require review. Local analysis is capped at 12000 characters; preview/cloud samples at 1500. Office bytes are never included in cloud payloads, and cloud authorization is unchanged.

## Isolation and hard budgets

- Existing 20 MiB file, 50-file / 200 MiB batch and two-slot preprocessing admission remain unchanged. New formats use the same two disposable parser slots as PDF.
- One spawned daemon process per parse, parent deadline at most 12 seconds (including spawn), cancellation checks at most 100 ms apart while waiting. Cleanup terminates, joins for up to 3 seconds, then kills if necessary; shared slots are always released.
- Windows job-object per-process committed-memory cap 384 MiB and kill-on-job-close, assigned before the worker receives permission to parse. Non-Windows uses 384 MiB RLIMIT_AS before extraction. Failure to assign Windows isolation fails closed. No long-lived Office parser is retained.
- ZIP: at most 512 directory entries, 8 MiB per uncompressed member, 32 MiB total advertised uncompressed bytes, ratio at most 100:1 per member, only stored/deflate. Compressed input remains at most 20 MiB. Actual XML reads are capped at 8 MiB + 1 and checked against advertised length/CRC by `zipfile`.
- Member names reject absolute filesystem paths, traversal, backslashes, control/NUL, URI punctuation/percent escapes, case-colliding duplicates and symbolic links. Names normalized by `zipfile` are rejected using `orig_filename`. No extraction to disk occurs.
- Macro/VBA, ActiveX, embedded objects, external-link parts and their dangerous content types/relationship types are rejected. Every XML/relationship part (also XML identified by content type) is validated, including unused parts. Relationships reject external mode, URL/scheme/percent-encoded targets, package escape and missing targets. Expected main content type, package root relation, main XML root and referenced slide/sheet types are checked; renaming a DOCX to PPTX fails.
- XML: at most 64 nesting levels, 256 attributes per node, 200000 nodes per XML document and 200000 aggregate preflight nodes. `TreeBuilder.doctype` rejects every DTD before entity expansion independent of UTF-8/UTF-16 encoding; unsupported encodings such as UTF-32 also fail closed. No entity resolver/network reader is installed.
- Text collection: at most 4096 nonempty units, 2000000 collected characters; exceeding these is disclosed as partial reading. Character sampling preserves separated head/middle/tail fragments, then maps them back to actual source units. XML preflight still checks omitted members.
- XLSX: at most 128 sheets and 100000 cells, valid Excel row/cell coordinates. CSV: 65536 characters per field, 1024 columns per row, 50000 logical rows, 100000 fields; over-budget CSV is rejected. CSV parsing runs inside its disposable worker so `csv.field_size_limit` cannot mutate server-global parsing state.

These limits intentionally reject some otherwise valid complex Office documents; they are operational limits, not a claim to support every OOXML feature or to prove document truth.

## Error interface

`OFFICE_INVALID_CONTAINER`, `OFFICE_FORMAT_MISMATCH`, `OFFICE_ENCRYPTED`, `OFFICE_UNSAFE_CONTENT`, `OFFICE_ZIP_LIMIT`, `OFFICE_XML_UNSAFE`, `OFFICE_XML_LIMIT`, `OFFICE_PARSE_FAILED`, `OFFICE_NO_TEXT`; `CSV_INVALID_UTF8`, `CSV_INVALID`, `CSV_LIMIT`, `CSV_NO_TEXT`; `DOCUMENT_PARSE_TIMEOUT`, `DOCUMENT_PARSE_CANCELLED`, `DOCUMENT_PARSE_FAILED`. Existing `FILE_TOO_LARGE`, `PARSER_BUSY`, `PARSER_ISOLATION_UNAVAILABLE`, source/library identity and hash errors are reused. Opaque CFB containers (encrypted OOXML or old Office containers) fail closed as `OFFICE_ENCRYPTED`; legacy DOC/XLS/PPT extensions remain unsupported.

## Independent review fixes: P2-3 / P2-4 and launcher import

The first review correctly reproduced two table issues in the initial extraction commit. The original report's word "adjacent" described output order but did not guarantee actual source-cell adjacency. That guarantee now follows XLSX column coordinates and DOCX physical cell indexes: empty, missing, hidden, formula-without-cache and error-valued cells leave their separators in the extracted row. A label in A followed by an omitted/empty B and unrelated C text remains `label\t\tC-value`, so the immediate-value rule cannot borrow C. XLSX rows with duplicate or descending column coordinates fail closed. Collection budgets count retained separators too; once collection is exhausted, later units cannot be joined across the omitted content. Plain two-column tables and independent paragraphs retain their earlier behavior.

Evidence entirely inside one source unit retains exact unit-relative `start/end` and its cell/paragraph metadata. Cross-unit evidence gets only the scope shared by every contributing unit (e.g. XLSX sheet+row or DOCX table+row); it receives no misleading first-cell/paragraph character range. This uses existing row fields, with no new frontend data shape.

Root browser testing also exposed a spawn-main import hazard: importing `neatdrop.app` eagerly imported `offline`, which imported NumPy in a child already assigned its 384 MiB job limit. `offline_status` now imports inside the config route. The real launcher regression imports `create_app` at top level, verifies no NumPy initialization, then starts the actual bounded CSV worker successfully. This avoids loosening the worker budget. Entrypoint code that actually runs server loops still needs its normal `if __name__ == '__main__'` guard.

## P2-4 follow-up: Unicode source offsets

Follow-up review found that calling `.casefold().find()` and applying the resulting index directly to raw text shifted locations after length-changing folds such as `ß → ss`. New purpose evidence already preserves its original source excerpt, so mapping now first uses exact raw substring search. Legacy normalized rule excerpts fall back to NFKC/casefold lookup with both normalized boundaries mapped through bounded raw prefixes; the entire candidate raw slice must normalize back to the complete excerpt before any coordinates are returned. End positions use the verified raw interval length, including expansions/composition, and an unverifiable fallback publishes no invented coordinates. Cross-cell row-only behavior is unchanged.

Added regressions cover the review input `ＡＢＣ Straße é` before the document title (raw title start 14), `Straße` and decomposed accents inside field values, fullwidth legacy invoice anchors, fullwidth colon and preserved padding.
