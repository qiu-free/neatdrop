## 2. 推荐方向与取舍

推荐“通用分类体系＋科研图表优先补齐，图片网格＋归档位置预览”。依据是用户需要日常综合整理，而现场暴露最明显的漏项是图表图片。

| 方向 | 收益 | 代价 | 选择 |
| --- | --- | --- | --- |
| 扩充静态类别、保留当前界面 | 改动小，能立即提供图表手动归档入口 | 分类越多，下拉框越难用；操作疑惑仍在 | 仅作为基础任务 |
| 分类扩充＋模板/标签＋图片工作台 | 类别可搜索，图片可直观看到；归档目标始终明确 | 需要同步类别、识别、目录兼容与交互状态 | 推荐 |
| 所有图片交给更大模型并自动整理 | 有机会覆盖更复杂内容 | 当前无质量/资源证据，且用途存在主观性；自动执行风险增大 | 不作为本轮前提 |

不以新增类别数量衡量完成。每一类都要有定义、反例、手动入口、输出目录和识别能力状态。识别未验证的类只能手动或给候选。

## 3. 分类体系

### 3.1 三个信息分别表达

| 信息 | 示例 | 对目录的作用 |
| --- | --- | --- |
| 文件格式 | PNG、JPG、PDF、TXT | 保留格式，不代表用途 |
| 图片/内容类型 | 数据图表、自然照片、票据影像、聊天截图、流程图 | 帮助理解内容和选择识别路径 |
| 归档用途 | 学习科研/数据图表、工作办公/项目报告 | 决定唯一归档目录 |

辅助标签可表达“直方图”“实验结果”“项目A”。标签不生成多个副本，也不改变主归档路径。不能从一张带狗图片的饼图或图例单词就把它归为宠物照片。

### 3.2 首批扩充建议

保留既有类别 ID 与目录的兼容性，新增类别通过服务端唯一配置下发到前端。避免目前前后端手工重复维护分类表。新旧交易按执行时固定路径查询与撤回。

| 分类域 | 首批需要补齐的用途 | 边界 |
| --- | --- | --- |
| 学习科研 | 数据图表、实验资料、研究数据、技术文档、读书摘录 | 图表类型作为标签；不因文件名 `Figure` 单独确定科研用途 |
| 工作办公 | 表格数据、演示资料、项目方案、需求设计、邮件存档 | PPTX/XLSX 等手动归档与内容识别支持分开标注 |
| 图片与设计 | 图标/标志、界面设计、流程/架构图、参考素材 | 素材用途主观时需人工确认 |
| 生活与家庭 | 家庭资料、保修说明、住房物业、保险资料、旅行资料 | 隐私资料本地处理，不提取身份或向外发送 |
| 财务 | 银行材料、缴费凭证、税务材料 | 不把字段教程或模板当真实凭证 |
| 技术开发（新域候选） | 源代码、配置文件、日志、数据库/数据集、软件包 | 先明确可支持格式；识别不等于运行、安装或导入 |
| 音视频与压缩包（新域候选） | 录音、视频、压缩包 | 若扩展安全副本支持，则只按格式/人工用途归档；不默认解析媒体或解压 |

后两项应单独核定范围：它们涉及新的文件类型，不因为目录类别新增就声称已能安全解析或识别。第一交付点必须先解决已支持格式中的分类缺口与界面问题。

### 3.3 分类选择方式

- 常用/最近使用分类作为快捷入口；完整分类可搜索，展示定义与例子。
- 提供“通用日常”“学习科研”“工作项目”视图模板。模板控制常用入口，不擅自更改旧分类 ID 或迁移已有目录。
- 手动选定分类后显示具体相对目录，不用不透明的类别编号代替目的地。
- 自定义分类后续增加，优先支持在现有主分类下创建安全子类；服务端生成稳定 ID 并校验名称、保留名、规范化冲突、路径越界。不能直接把用户字符串拼成路径。

## 4. 工作台交互

### 4.1 起步就说明整理范围和位置

选择目录后固定显示两行：

> 整理来源：你选择的文件夹。  
> 副本位置：该文件夹内的分类子目录。原件保留。

扫描完成后明确显示：“可处理文件 X 个，子文件夹 Y 个（当前不进入），暂不支持 Z 个”。提供单独选择子文件夹的入口；不暗中递归。后续若增加递归，必须另有开关、深度/总数限制与排除归档目录规则。

### 4.2 让状态帮助用户行动

把主流程文案变为“选文件 → 获取建议 → 核对后生成副本 → 查看结果”。每一步只有一个明确的主按钮；分析模式和高级设置移入次级区域。

建议状态采用具体文案：

- “可快速核对”：已有充分依据，尚未人工确认。
- “需要你选分类”：存在候选或子类不清楚。
- “尚未识别”：没有有用候选，提供手动分类入口。
- “已确认”：当前名称和位置已核对；编辑后恢复未确认。

“正在查看”只表示预览焦点。勾选框只表示加入批次，必须能在复核前选择文件；确认状态单独管理，执行时再严格检查。当前待复核项目被禁止勾选，会使“想处理但不能选”变成隐藏门槛，应移除这一限制，同时保留最终确认门槛。

### 4.3 图片优先的查看方式

图片批次默认网格，文档保留表格，允许切换。每张卡展示缩略图、原名、建议分类、状态和选择框；不在卡片堆叠主类/子类/形式/多种技术状态。

详情按用户决策顺序展示：

1. 大图与放大/缩小、适应窗口；OCR 区域按需叠加。
2. “识别到什么”：例如“数据图表，可能为直方图”。
3. “建议放哪里”：完整分类与实际目标路径。
4. “你需要确认什么”：最多一个主要问题，候选可直接选择。
5. 名称与“确认此项”按钮。

OCR 原文、模型版本、抽样预算和证据详情折叠为“识别详情”。主界面避免只显示 `Logs`、`screenshot` 或其他技术词作为完整依据。

### 4.4 归档预览与结束

进入最终确认前就能看到每个文件的“原名 → 副本名”“来源 → 目标”。点击确认生成计划后路径固定，执行仍须明确确认。

完成后显示“成功生成 N 份副本，原件保留”，提供查看目标目录、操作记录和可信撤回入口。打开目录仅打开已核验的当前工作区子目录，不执行文件内容。新增打开功能需按本机桌面支持范围实现。

## 5. 图片分析

### 5.1 先识别内容类型，再推断用途

新增至少以下类型候选：数据图表、表格影像、流程/结构图、文档扫描、应用截图、聊天截图、自然照片、设计/绘画、混合内容、未知。

图表不默认等于科研资料：可以是办公报表、个人记账或教学示例。类型“直方图”和用途“学习科研/数据图表”分别展示，缺少上下文时只建议用途并要求确认。

### 5.2 图表专门路径

组合使用：

- 全图与有限局部视图的视觉候选，加入折线、散点、柱状、直方、饼图、热图、箱线、流程图等内容定义和反例。
- OCR 的标题、轴标签、单位、刻度、图例位置，保留文字框。不能只靠一个英文标题决定类型。
- 轻量几何证据辅助识别坐标轴/绘图区/重复柱形等结构；几何和视觉模型都只是线索，必须用真实对照测试确认收益。
- 融合冲突时优先保留“可能为数据图表”的类型候选，允许拒判细分；避免强行落入 screenshot/illustration/photo 既有标签。

首期只做类型、用途、保守标题建议，不做图表数值还原、趋势结论或学术内容解释。OCR 无法读出的标题不补造；没有可靠标题时保留文件名。

### 5.3 模型选择

先用现有模型建立扩充提示与结构证据的基线，再对比适合中文的视觉模型或小型本地视觉分类器。部署权重固定版本、哈希和许可，运行时只加载本地文件。

本地视觉语言模型可作为明确选择的增强档，先做硬件、耗时与任务质量验证；缺失时回到已验证路径。云端只在逐批授权后使用，不因离线识别困难自动切换。此前 BGE 文本候选模型没有证明额外收益，不能用“打开实验开关”代替图片升级。

## 6. 验收

### 6.1 功能与安全

- 分类表后端唯一来源；新类别目录安全、旧计划/记录/撤回兼容。
- 图片网格、文档列表、缩放、候选选择与状态变化可键盘操作，窄屏不横向溢出。主要文字和控件需重新测量字号/对比度，截图不能证明 WCAG 合规。
- 待复核文件可以加入批次，但未确认不能生成执行计划；修改分类/名称使旧确认与旧计划失效。
- 来源、子文件夹处理方式、副本位置与占用空间在主流程可见。
- 图片/模型资源预算、取消、断网本地运行、原件摘要保护与可信撤回回归通过。

### 6.2 图片质量

先建立独立于开发修改的授权图片评测集，覆盖图表各类、照片/海报、文档/票据、应用/聊天截图、混合/低清/旋转内容，并按来源/模板分组，防止裁切近重复泄漏。

用户当前这批图表可以作为问题复现依据；不得未经明确授权复制进训练/长期评测目录或上传模型。本轮只看了应用内已有预览，不转作持久样本。

分别报告：类型命中、归档用途命中、Top-3、错误普通建议、候选/拒判、耗时和内存。图表子集需要和当前十场景模型独立对照。整体准确率不能掩盖“图表改善、照片退化”。

### 6.3 可用性

邀请不了解实现的人完成四个任务：选择包含子文件夹的目录、纠正一张图表、说明文件将存在哪里、生成并撤回副本。观察是否需要口头提示、是否误以为分析已经移动文件、是否看懂不能继续的原因。

## 7. 实施顺序

1. 分类表单一来源、补数据图表等首批用途、显示目录/扫描范围；不更换模型，先完成可手动纠正的闭环。
2. 图片网格和大图详情、精简状态与主按钮、归档位置预览、可解释的执行门槛。
3. 图表专门识别与真实独立评测，对比模型/结构特征收益，达到门槛后才启用普通建议。
4. 再评估自定义分类、更多格式、递归与本地视觉语言模型。它们分别增加范围，不作为前三项的前置条件。

当前草案没有改动分类运行逻辑或界面，下一步先确认上述信息结构和首批类别范围，再把工作台布局做成可审阅的视觉方案。

优先采用“文件网格＋常驻大图/归档详情”布局与后三项状态/选择反馈。Masonry 已在组件目录找到，但其瀑布流高度变化与批量复核的空间记忆相冲突，首期使用固定比例的规则网格，不默认上瀑布流。强透视卡片、跟随光标、粒子背景、逐字动画不进入工作区。

### 8.2 动效约束

- 原位状态和颜色过渡约 120–180ms；详情中不能动画 height、top、margin 或整体位移。
- 预览加载占位、成功和错误共用固定区域。切换时不显示上一文件内容，也不通过淡出把旧图留在新名称下面。
- 选择/确认反馈只作用目标控件；语义上独立的“正在查看”“加入批次”“已确认”不能用同一种动效混同。
- 所有动效遵守 prefers-reduced-motion；键盘、焦点、触屏与无动画状态同等可用。

### 8.3 已授权 bug 修复

现场复现：从饼图详情点“下一个文件”，页面 scrollY 从约595px跳到26px；详情面板因 file ID 改变 key 被卸载重建，导航 effect 对新按钮调用 focus()，浏览器把它滚入视口。预览短暂变成“读取中”也会改变高度，面板滚动与滚动条宽度随内容变化。

修复范围：详情 key 只与工作区绑定，切换时保留 DOM 与内部滚动；所有导航/抽屉焦点使用 preventScroll；移除固定抽屉入口多余的 scrollIntoView；预览220px固定占位、详情使用视口内稳定高度、预留滚动条。增加最多8项/8MiB的会话内预览缓存，键由工作区/文件ID/内容摘要组成；切换工作区或卸载释放，不写浏览器存储，异常不缓存。
