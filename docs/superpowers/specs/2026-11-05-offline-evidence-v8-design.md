# v8 离线证据与内容召回改进

日期：2026-11-05。承接已确认的离线多证据方案；本轮收敛为现有规则链的改进，不引入新模型或新的持久化子系统。

## 现有证据

基线 `281f11a`。只读合成诊断复现：只有“课程笔记”或“电子普通发票”标题、正文没有对应支持时仍能成为普通建议；自然表述的学习/会议/研究内容、业务台账、需求说明和部分账户办理同义标题会漏识别。原开发集40项中35项有标签，首选子类命中31项，4项未命中。v7的338个相关行为检查仍通过，不能因此说明真实文件准确。

代码还存在扫描PDF不做OCR、OCR不按版面恢复键值关系、人工纠正未进入学习等限制。本轮不把这些独立工程混入规则修复，也不把旧BGE语义实验默认开启：既存开发对照没有测出其命中收益。

## 本轮行为

1. 旧显式规则的正文支持必须位于用途标题/锚点之外，重复标题不能充当独立证据。只有标题或文件名时仅给候选。
2. 发票额外核对实际开票字段，空字段或单纯列举字段不升级为普通建议。保留无冒号OCR字段的兼容；不将分隔后的下一个字段借作当前值。
3. 对学习过程、研究叙述、会议讨论和业务台账增加多组结构线索，全部保持待复核。单个“研究”“讨论”或表格格式不足以赋予用途。
4. 教程明确引用票据/合同等示例时，优先提供学习用途候选，保留被引用用途为其他候选及示例/冲突提示。
5. 为“需求说明”“账户业务办理确认”补同义锚点，继承原有至少两组非空字段和待复核门槛。
6. 新结构候选在OCR与视觉融合时仍可保留，不能被普通物体场景覆盖；只有孤立标题时不抢占照片判断。依据使用真实连续原文，现有抽样坐标映射继续生效。

## 边界与文件职责

- `classifier.py`：显式规则独立支持、发票字段和同义用途；调用结构候选模块。
- `content_signals.py`：有界自然语言/表格/示例上下文信号，仅产生待复核候选，无文件访问或模型调用。
- `analysis.py` / `decision.py`：引擎版本和既有候选门槛；接口与目录不变。
- `types.ts`：解释新增复核原因；不改审核和复制授权。
- 专属测试与v8对照：冻结v7代码，分别报告旧集、新诊断、反例、实际格式提取与图像候选融合。

## 验证标准

先写失败回归再修改。旧40场景逐项比较，允许4个已声明错误的标签改善及证据不足场景从普通建议降级；其他标签不得无解释改变。既有298个非旧40的v7行为检查保留。新增普通建议误报反例、多证据自然表述的正反例、否定/模板/空值、图像冲突、原文坐标与真实CSV字节测试。全量后端、前端和生产构建通过。

开发命中、普通建议错误、拒判和覆盖分别计数。新用途中没有真实独立校准的仍只给候选，不以复核数下降替代准确率提升。没有代表性真实文件集，不能承诺整体准确率。后续优先收集用户明确选择、逐项标注且保留在本机的误分类样本，再决定扫描PDF OCR、纠正记忆或新的本地模型路线。

## 最终验证发现的既有撤回问题

全量回归复现Windows重命名错误123或目标后缀异常；固定v7归档隔离运行也复现。
合成文件的分配器尾部探针证明`FILE_RENAME_INFO`文件名没有预留WCHAR结束符时会
受边界外内容影响。附加一个WCHAR零终止位置并传递明确缓冲区大小，保留原有
禁止覆盖、文件身份、哈希及锁定句柄检查；用真实原生调用失败→成功回归验证。
