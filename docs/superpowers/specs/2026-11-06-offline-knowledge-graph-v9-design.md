# NeatDrop 离线知识图谱 v9 设计提案

日期：2026-11-06。状态：已实施并验收，包含用户指定的 Graphify 图谱形态。具体实测结果与限制见 [v9交付记录](../../v9-delivery-2026-11-06.md)。

## Graphify 形态修订（2026-11-06）

用户明确要求“知识图谱的形式采用 graphify 的形式”。本节替代下文旧版树形分类布局及其默认折叠规则，其余可信文件、关系依据、离线处理和持久化约束继续适用。

已实际浏览官方 [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify)、[官网](https://www.graphify.com/) 及仓库的 [graph-hero.png](https://raw.githubusercontent.com/Graphify-Labs/graphify/v8/docs/graph-hero.png)。官方图展示深色背景上的力导向网络，用不同颜色标注社区，右侧列出社区及数量，支持节点点击、筛选及搜索。NeatDrop 采用该图谱形态与交互思路，以已有分类作为可解释的分组；不把分类分组称为算法发现的语义社区。

- 默认进入“全局图谱”：深色关系画布、圆形节点、按分类着色的自然聚类网络；移除单一“归档资料”根节点和从左到右的树形排布。分类与子分类使用有标记的圆形聚合节点，文件显示为可点击的圆点；节点大小体现聚合数量或实际连接数，颜色和文字共同表达类别。
- 右侧提供“分类分组”及数量、搜索和关系筛选。默认展示可控数量的文件，使少量归档资料立即成为网络；支持按组收起、继续显示，画布仍最多 200 个节点，所有文件保留在可访问列表中，并清楚显示画布截断。
- “局部关系”以当前文件及一层邻居为中心。悬停或选中时高亮相邻节点与连线，弱化其余内容；点击文件继续使用可信预览侧栏，点击关系查看双方依据。分类边、归档重复、候选和人工关系保持不同来源及线型。
- 力导向计算必须有界，并在数据结构变化或显式重排时执行；选中文件、打开预览、切页和返回不重启布局。用户拖动位置与本次会话的视角应保持稳定。减少动态效果时无布局动画。
- 深色仅用于图谱工作区，外层继续现有主题。控制和侧栏保持清晰的文字对比与可见焦点；窄屏将分类面板放在画布下方，文件预览为全宽。
- 所有图谱库随本地构建交付，无 Graphify 云服务、账号、遥测或运行时依赖；关系提取仍使用已经实现的 NeatDrop 本机索引，不引入外部语义模型。

## 目标与现有基础

将当前授权目录内已经归档的文件和图片组织成可浏览的知识图谱。用户能看清资料的类别，找到相关文件，并检查每条关系的来源。图谱是资料库的一种浏览与关联方式。

当前 ArchiveLibrary 已从校验过的事务日志和本机可信回执生成资料库，提供稳定的归档记录 ID、主分类、子分类、生成时间、相对路径和可用状态。当前分类包含 9 个主分类和 57 个子分类条目；没有持久化的全文关系索引。

首版继续使用现有归档分类、可信读取和撤回流程。图谱不会改变原件、归档路径、分类标准或执行确认步骤。

## 原方案参考与取舍（布局已由 Graphify 修订替代）

实际浏览的参考：

- Obsidian Graph view：https://obsidian.md/help/plugins/graph 。采用全局概览、局部邻居、搜索筛选和悬停高亮的交互思路。Obsidian 的连线来自内部链接；NeatDrop 必须单独定义文件关系来源。
- Kumu Cluster：https://docs.kumu.io/guides/clustering 。采用把分类字段转为聚合节点的思路，减少同类别文件之间重复连线。
- Cytoscape.js：https://js.cytoscape.org/ 。已查看 concentric-layout 示例；其节点、边、分组与布局能力适合作为图谱渲染基础。示例中的密集同心圆仅供布局机制参考，不直接作为产品首页。

考虑三种形态：

| 形态 | 优点 | 局限 |
| --- | --- | --- |
| 分类树 | 结构明确、容易理解 | 难以显示跨分类文件关系 |
| 全量关系网 | 能展示跨文件连接 | 文件多时文字和连线拥挤，导航成本高 |
| 分类概览＋文件局部关系网（推荐） | 分类清楚，按需探索关联 | 需要提供两个视图和清楚的切换入口 |

## 首版页面与工作流

主导航增加“知识图谱”，与资料库共用当前授权目录。在资料库文件详情中增加“在图谱中查看”，在图谱中可返回资料库。

1. **进入分类概览**：默认只呈现有归档记录的主分类、子分类及数量。空类别可通过筛选查看，不把所有文件一次铺开。
2. **展开分类**：点击主分类、子分类逐层展开文件。每个文件显示可辨认的名称、文件类型标记和可用状态。展开、折叠只改变图谱显示。
3. **查看文件**：点击文件打开右侧详情，包含可信预览、分类、来源、实际相对路径和关联文件。切换文件保持侧栏容器及预览占位高度稳定。
4. **聚焦关联**：选择“查看相关文件”切换到以该文件为中心的一层关系图。用户可返回分类概览，保留之前筛选及视角。
5. **发现内容线索**：点击“分析关联”，在说明本地索引内容后，分析所选的已归档副本。提供数量、进度、取消、完成数和失败原因。
6. **确认或补充关系**：用户可以确认、忽略候选，也可以选择另一份归档文件，手动添加关系。

顶部提供文件名搜索、分类筛选、关系类型筛选、重置视角、刷新和索引管理。搜索结果也提供可键盘操作的文件列表；点击结果定位对应节点。

未选择目录时引导返回工作台；没有归档记录时说明“分析 → 审核 → 确认生成副本 → 图谱”的流程。只有分类信息、未建立内容索引时，明确显示“类别关系已就绪，尚未分析内容关联”。

## 节点与关系的含义

首版节点仅包含主分类、子分类、归档文件。主题、项目、人物、地点实体暂不自动生成，避免把弱线索包装成事实。

| 关系 | 来源与含义 | 呈现 |
| --- | --- | --- |
| 分类包含 | 来自已归档记录的主分类、子分类 | 实线，显示“属于”或“包含” |
| 归档时内容相同 | 两个可信归档记录的 SHA-256 相同 | 实线，说明比较的是归档时内容；核验当前副本后才说明当前内容相同 |
| 文字线索相近 | 本机从正文或图片 OCR 中发现可核对的共同关键词 | 虚线、“待确认”；可查看共同词和双方证据 |
| 视觉相近 | 本机图片感知指纹接近 | 虚线、“待确认”；显示双方图片和相似依据，不推断人物、事件或地点 |
| 人工关系 | 用户手动添加或确认的关系 | 实线，标明“人工确认”和时间 |

同类别通过分类节点聚合，不在同类别的每两份文件之间生成连线。同批次归档只作为来源信息，不自动作为内容关系。同名、相同扩展名或相同大小不足以认定重复文件。

人工关系预设为“相关资料”“引用参考”“配套说明”“版本关系”。有方向的关系必须在表单中用两个文件名说明方向；不自动根据名称推断引用或新旧版本。

点击关系后，详情展示：双方文件、关系类型、生成方式、索引时间、共同线索、读取范围及质量限制。匹配分值只表达算法排序，不显示成分类准确率或事实概率。

## 离线关联分析

分类概览只读取既有归档元数据。正文、OCR 和图片指纹分析由“分析关联”显式触发，全程使用本机依赖，无云端请求或运行时下载。

首版方法：

- 文本采用中文字符片段与英文词项的 TF-IDF 加余弦相似度；清理停用词、文件格式词和通用模板词。候选必须具有双方可定位的正文共同线索，不能仅凭文件名或分类一致生成。
- 图片有可读文字时，可参与同一文本关联流程；另以方向校正后的图片感知指纹提供视觉相近候选。无可靠文字的照片不伪造主题描述。
- 沿用现有内容质量诊断。乱码、空白、OCR 分值低或读取不完整时，展示限制；不足以支持匹配的材料不产生相应候选。
- 每个文件最多连接 5 条自动关联候选边，先按分值稳定排序，再同时检查两端候选数；人工关系不受此上限限制。阈值在开发样本上确定，用独立验收样本检验。用户可忽略候选；内容和算法版本未变化时，重新分析也不重复提示已忽略的同一候选。
- 首版不依赖本地大语言模型、CLIP 或向量数据库。当前语义候选默认关闭，不能据此承诺可靠的知识关系。

每批最多 50 个文件、单文件最多 20 MiB、总量最多 200 MiB，延续现有解码限制和最多 12000 字符的文本采样。图片沿用像素限制和隔离执行；扫描版 PDF 在现有解析能力不足时报告原因。索引任务逐项处理，并提供取消和有界执行。取消不发布该批未完成的新索引，保留之前有效快照。

## 数据与接口边界

数据流：可信归档记录 → 分类图投影；用户触发分析 → 安全读取副本 → 有界提取与质量检查 → 本地关联候选 → 用户确认或忽略 → 关系图。

后端新增独立图谱模块，不改变归档日志格式，不从客户端接收文件路径。所有接口先校验会话及当前目录授权，仅接受归档记录 ID。

建议接口：

- `GET /api/v1/workspaces/{id}/graph`：返回分类、文件、关系摘要、截断标志和索引状态。
- `POST /api/v1/workspaces/{id}/graph/jobs`：按归档记录 ID 启动本地分析；配套任务查询和取消接口。
- `GET /api/v1/workspaces/{id}/graph/relations/{relation_id}/evidence`：重新核验副本后返回有界证据。
- `POST /api/v1/workspaces/{id}/graph/relations`：添加人工关系或确认候选。
- `POST /api/v1/workspaces/{id}/graph/relations/{relation_id}/dismiss`：忽略候选。
- `DELETE /api/v1/workspaces/{id}/graph/relations/{relation_id}`：删除人工关系，仅删除关系元数据。
- `DELETE /api/v1/workspaces/{id}/graph/index`：清除该目录的内容索引和自动候选，保留人工关系。

图谱本地数据存于安装目录的 `.neatdrop-state/knowledge-graph/` 下。服务端根据已规范化的目录路径与根目录身份派生隔离键；同目录重新授权可恢复，名称相同的其他目录不能复用。

持久数据包括索引格式版本、归档 ID、内容摘要与文件身份、算法版本、有限词项和位置锚点、图片指纹、人工关系及忽略记录。首次分析前说明会在本机保存关键词等衍生信息，并提供清除入口。全文、预览图和原始 OCR 全文不持久化，证据按需安全读取。状态文件不纳入 Git。

使用有版本及修订号的结构化本地文件，单目录最多 1000 个文件索引、5000 条人工关系，每文件最多 256 个词项、每词项最多 3 个位置锚点；索引快照最多 16 MiB，关系状态最多 2 MiB。超限报告原因，不静默覆盖已有数据。写入采用受保护目录、原子替换与锁，沿用现有安全 I/O 边界。读取或恢复异常时保留分类概览，提示关联索引不可用并支持重建。不要从用户目录内任意 JSON 恢复可信关系。

每次展示图谱时与当前资料库求交。已撤回文件及其关系不再显示；缺失、变化、未验证项保留状态但禁用内容读取与新候选。缓存只表示过去的分析快照，不能证明副本当前未变化。返回证据和确认自动候选前，必须重新核验身份、大小及哈希；任一端不符则拒绝并要求重新分析。

## 前端实现方向

沿用当前森林绿主题、15px 正文、13px 辅助文字、清晰边界及侧栏交互。分类颜色只作辅助，同时保留名称、图标与线型。

推荐以 Cytoscape.js 渲染图谱，随前端构建打包，不使用 CDN。React 负责导航、筛选、文件列表与详情。图谱组件独立管理实例并正确清理；分类布局使用确定性位置，避免每次选择都重启力导向布局。

分类总览最多沿用资料库最近 1000 条记录并明确提示截断；默认聚合节点，每个子类按 50 个文件展开，画布同时显示至多 200 个节点。局部关系默认一层、最多 20 个邻接文件，额外结果通过列表继续查找；不因渲染上限静默丢失搜索结果。

支持缩放、拖动画布、适应视图及局部高亮。过滤、选择和切页保留本次会话中的视角，切换授权目录清空旧视角；不把用户路径写入浏览器持久存储。尊重系统减少动态效果设置。

复用资料库可信预览内容和请求管理。桌面采用右侧详情，窄屏改为全宽详情；关闭、Escape、键盘焦点、触发点返回和背景交互规则保持明确。画布配套同等功能的文件与关系列表，避免只能使用鼠标。

## 验收标准

1. 新归档文件出现在对应主分类和子分类；刷新、重启并重新授权同目录后，结构与人工关系可恢复。
2. 从文件到关联文件可直接打开可信预览；过滤、展开、聚焦与返回不闪烁、不重置视角；验证 1440px 桌面与 390px 窄屏。
3. 所有关系均有明确类型和来源；点击自动候选能够检查双方证据；候选不会自动升级为已确认关系。
4. 独立合成样本覆盖中文、英文、跨格式正文、图片 OCR、近似图片及无关文件；验证同名异内容、同模板不同事项、同类不同主题和低质量 OCR 不产生误导性事实关系。
5. SHA 重复判断覆盖同名不同内容、异名相同内容和同大小不同内容；“文字相近”或“视觉相近”永远不能标成“内容相同”。
6. 关联精度以独立标注候选集计算，固定版本的验收集至少包含 40 组相关、40 组易混淆无关样本，混合中文、英文、跨格式和图片场景。首版目标为候选精度至少 90%，可读取相关样本中每个文件至少找回一条已标注关系的比例至少 60%；另报无结果和质量受限数量。这些数值是验收目标，不能当作已测成绩或真实用户资料上的保证。不以分类测试成绩代替，抽取能力不足的文件明确显示限制。
7. 未授权目录、任意路径、伪造记录、链接替换、同大小改写、缺失副本、撤回、损坏状态与跨目录 ID 测试通过；旧缓存不能绕过证据读取核验。
8. 索引进度、取消、重复点击、任务竞争、失败后重试及修订冲突均有稳定状态；清除内容索引不影响文件或人工关系。
9. 阻断外网后，分类概览、索引、人工关系、搜索、预览全部可用，无 CDN、模型下载或云端调用。
10. 验证 1000 条归档记录下的聚合、搜索和 200 节点渲染；记录开发机操作耗时。完成前后端测试与生产构建，并实际走通“归档 → 图谱 → 分析关联 → 确认关系 → 重开 → 撤回”。
