# NeatDrop 知识图谱重新规划：参照本机 Obsidian

日期：2026-11-07（Asia/Shanghai）。项目基线：`a7dbe15`。
本文为本轮规划交付，不代表已完成程序实现或运行验收。

## 1. 现场参考和设计结论

本轮通过桌面界面实际查看了用户电脑中的 Obsidian 1.15.0 关系图谱及其设置面板，
没有读取笔记正文，也没有复制笔记名称或关系数据到项目。

实际观察：

- 白色大画布，主体是深灰中心节点与较小的浅灰外围节点，外围分布自然。
- 一个整体网络中包含多个关联簇；簇之间的真实连接没有被强行切断。
- 独立节点与独立小簇位于整体网络外围，不被要求占据规则网格。
- 图谱设置是画布右上角的浮动折叠面板，包含“筛选、颜色组、外观、力度”。
- 本机外观设置的文本透明度为0，节点大小与连线粗细各为1.00，箭头开关关闭。
- 力度设置可分别调节：图谱向心力、节点间排斥力、相连节点吸引力、连线长度。
  现场数值依次为0.52、10.00、1.00、250。这些是 Obsidian 的引擎参数，
  作为调节维度的参考，不直接复制为 NeatDrop 引擎的数值。

当前 NeatDrop 将连通组安排为规则的独立短弧/分支，节点尺寸近似相同，
固定300px工具列和500px画布占用了较多操作空间。它解决了一部分交叉，
但呈现出来更像多组链条，难以一眼看出中心文件、密切邻居及簇间关系。

新方向：**以画布为主，按真实文件关系自然聚类，用节点大小表达连接层级，
把筛选与显示调节收进面板，以稳定的二维浏览为默认，提供可切换的三维探索。**

## 2. 页面布局

### 桌面

沿用 NeatDrop 全站侧栏、导航、浅色主题，调整知识图谱页内部结构：

1. 页标题与说明缩成紧凑一行，不让长介绍和多行统计持续挤压画布。
2. 上方工具栏保留全局/局部入口、搜索、可见节点与关系数量、分析关联、图谱设置和展开画布入口。
3. 图谱区域占页面内容宽度，默认取消始终展开的300px右侧工具列。
4. 桌面画布建议高度为 `clamp(520px, calc(100dvh - 220px), 820px)`；
   1366×768时仍有520px可用区域，较高屏幕获得更大的关系浏览区域。
5. 右上设置按钮打开约280px宽的浮动面板；面板可收起，标题栏和关闭按钮始终可见。
6. 左下仅在悬停/选中时展示文件名、所属分类和当前连接数；不在每个节点下面铺文本。
7. 右下保留缩放、适合画布、恢复默认视图；底部简短说明“拖动平移，滚轮缩放，点击文件预览”。
8. 点击文件后沿用现有侧边预览；设置面板与文件预览避免同时展开遮挡画布。
9. 完整文件列表、关系列表保留在画布下方可展开区域，支持键盘访问和查找未绘制文件。

新增全屏/展开画布只针对图谱页，不改变文件、索引或全站其他页面。

### 手机

- 搜索与全局/局部入口保留在上方，低优先级动作放入更多菜单。
- 图谱设置使用底部抽屉，文件预览使用现有移动端详情形式。
- 默认二维；一指纵向页面滚动可用，进入“操作图谱”状态后支持平移/缩放，提供明确退出。
- 图谱操作、面板与文件列表均可通过按钮和键盘完成，不把手势作为唯一入口。

## 3. 节点与连线

### 文件节点

- 一个圆点对应一个真实归档文件，默认不显示下方文字。
- 节点按实际、去重后的可见文件邻居数量分级；并行关系不重复放大文件的重要性。
- 基础直径建议：普通文件7–9px，多个连接的文件10–14px，高连接度文件16–22px。
  按对数曲线平滑增长并设上限，避免一个文件遮住整簇。
- 真实圆点较小，但命中区域至少24px；键盘焦点显示清楚外环。
- 默认深灰中心、普通灰外围；孤立文件稍浅但保持清楚可见。
- 黑灰深浅表达连接层级与选中状态，不再随三维前后位置突然切换黑/灰。
- 可选“按分类着色”，使用中等饱和度的有限色组；默认仍为灰阶。
- 显式聚焦节点和搜索命中节点使用淡绿外环，符合全站浅绿主题。

### 关系线

- 延续用户已确定的曲线，采用轻微弯曲；同端点多条关系使用可区分的曲率。
- 默认中性灰细线约0.8–1.1px，较低透明度；悬停/选中后突出直接邻居和相关边。
- 不让全图所有线同时变粗；非相邻区域弱化，但文件仍可辨认。
- 人工/事实关系为实线，待核实候选为虚线；方向箭头默认收敛显示，
  选中有方向关系或开启“显示方向”时明确显示，依据面板始终说明方向。
- 同一对文件的多条关系可在默认远景合并显示为一束，选中后分开并列出数量与各自依据。
  合并仅是显示方式，不合并或删除关系记录。

## 4. 自然聚类与排布规则

### 采用稳定的力导向布局

将现有“连通组固定打包”改为“真实连接吸引、节点排斥、适度向心、簇间留白”的组合：

1. 以文件关系为输入，先识别关联簇及簇间桥接文件。
2. 高连接文件位于相应簇的内部，邻居在其周围展开；簇中心不是新增的虚拟文件。
3. 只有一两条连接的文件自然处于边缘，独立文件和独立小簇放在外围空白区域。
4. 节点碰撞半径依据视觉大小加点击缓冲计算，避免中心大点盖住小点。
5. 簇之间用较弱斥力保持留白，保留所有实际跨簇关系；不把每簇切成隔绝的方块。
6. 连接数量多的节点不允许因原始边数过多无限吸紧，布局时先去重相同端点，显示时保留所有关系。
7. 数据排序和初始位置确定，布局仅在首次载入、明显结构变化、调节布局或明确“重新整理”时运行。
8. 布局有迭代/时间上限，稳定后停止；选择、预览响应和鼠标悬停不启动全图重排。
9. 用户拖动的节点保留位置；搜索和筛选只改变可见性，返回时恢复原位置。
10. 新展开文件在原簇附近增量放置，仅允许邻近节点小范围让位，避免整图跳动。

### 拓扑必须真实

Obsidian 之所以有明显的星团，是因为库中存在大量实际链接的中心笔记。
NeatDrop 的现有合成资料主要是几条链，切换布局不会凭空变成许多大型星团。

- 有中心文件时呈现中心与外围。
- 只有链式关系时呈现自然短链，不强行制造中心。
- 没有实际关系时呈现独立节点，不因同类别擅自新增文件关系。
- 若日后增加“主题/概念节点”，应作为独立数据功能规划，明确提取依据和置信度；不在本轮用装饰点代替。

## 5. 浏览和选择

| 操作 | 建议表现 |
| --- | --- |
| 打开全局图谱 | 恢复上次视角，首次适配整体关联簇 |
| 拖动画布空白 | 默认平移 |
| 滚轮/触控板缩放 | 以指针所在位置为锚点；图谱获得操作焦点后接管缩放，普通页面区域仍能滚动 |
| 拖动文件点 | 调整节点，附近节点轻微避让，松手后稳定 |
| 悬停节点 | 强调当前文件、直接邻居、连接曲线，左下显示文件名和分类 |
| 单击文件点 | 选中文件并沿用侧边预览 |
| 选择“局部关系” | 以当前文件为中心查看直接邻居，后续可按需扩至2跳；默认容量仍有界 |
| 单击关系曲线 | 保留当前关系依据入口，并显示来源、类型与方向 |
| 点击空白 | 清除选中，不重新排布 |
| 搜索命中 | 高亮并提供“定位”；不在每次输入后强制全图缩放或移动 |
| 切换三维 | 在单独视角中旋转；退出恢复二维原位置与缩放 |

二维模式和三维模式分别保存视角，模式标识清楚；不以3D旋转替代日常的空白平移。

## 6. 右上设置面板

参考本机 Obsidian 的四个折叠分区，将现有能力放回合适位置：

| 分区 | NeatDrop 内容 | 默认策略 |
| --- | --- | --- |
| 筛选 | 文件名、主分类、关系类型、显示孤立文件、待核实候选 | 沿用现有筛选；孤立文件可见，候选线清楚标识 |
| 颜色组 | 灰阶、按分类着色、分类开关和数量 | 灰阶默认，分类色可选 |
| 外观 | 节点大小、线透明度/粗细、方向显示、二维/三维 | 无节点下方文字；灰线，二维默认 |
| 布局 | 疏密、连接距离、向心/排斥/吸引高级项、重新整理、恢复默认 | 优先给“紧凑/均衡/疏朗”预设，原始参数放高级折叠 |

“分析关联”和“管理本机索引”继续区分于视觉设置。
调节显示不读取更多文件内容、不隐式开始分析、不写回或删除关系。

## 7. 对现有代码的实施落点

本次仅给出落点，不在规划阶段改写应用：

- `frontend/src/graphLayout.ts`：引入力导向聚类、稳定初始种子、节点碰撞和增量布局；
  可保留现有分支排布作为减少动态效果或布局失败时的稳定后备。
- `frontend/src/graphProjection.ts`：保留可信文件/关系投影与200可见节点上限，
  补充去重邻居度数、簇标识与桥接信息；不更改后端关系事实。
- `frontend/src/components/GraphCanvas.tsx`：区分二维平移与三维旋转，按连接数绘制尺寸，
  处理悬停、选择、曲线合并/展开、可见区域和布局生命周期。
- 新增 `GraphSettingsPanel.tsx`：承载四个折叠分区，管理焦点、关闭和恢复默认。
- `frontend/src/components/KnowledgeGraphPage.tsx`、`graph.css`：紧凑页头、大画布、可折叠设置，
  继续使用现有 `LibraryDrawer`、文件列表、关系依据和本机分析流程。
- `frontend/src/graphTypes.ts`：增加显示模式和视觉设置，分开保存二维/三维视角；
  使用已有会话机制，不把文件正文和路径保存进浏览器持久存储。

是否引入额外图布局依赖应由实施时的小规模性能验证决定，所有依赖必须本地打包、离线可用，
保持现有 CSP，不使用在线字体或CDN。

## 8. 实施顺序与验收

1. 用同一套数据制作并确认“大画布+浮动面板+灰阶聚类”的设计稿。
2. 先完成自然聚类与节点层级，以星型、多中心、链型、环型、孤立文件分别验证。
3. 接入画布布局和设置，再完善二维/三维与预览交互。
4. 验证结构和交互，最后再调整配色、线透明度和动效。

验收数据至少包括：

- 原有24文件/21关系合成资料，用于判断旧分支是否退化。
- 3个真实中心各带若干邻居、中心之间有桥接的合成网络，用于验证与 Obsidian 相似的多簇形态。
- 200节点的高连接图、宽树、深树、环、多个孤立组；1000文件列表仍完整可访问。

验收要求：

- 高连接文件和普通文件的大小有层次，默认没有下方文字；节点点击区域不小于24px。
- 关系集合前后一致，虚线候选和方向可查证；每条关系仍能查看其依据。
- 同簇邻居靠近，不强制固定成相同圆圈或网格；跨簇连接自然保留。
- 布局稳定后无持续空转，切换文件不闪烁、不全图跳动，过滤往返恢复位置。
- 视角不被异步分析回包覆盖；用户拖动和重新整理有清楚的保存/恢复规则。
- 桌面画布占比明显增大；手机可滚动、可退出图谱操作，没有控件遮挡或横向溢出。
- 减少动态效果、键盘操作、预览关闭后的焦点恢复、离线资源和CSP继续通过。
- 力导向图不承诺任意网络零交叉；不通过隐藏真实关系取得整齐外观。
